# MCU TOOL 设备协议 v1

用户于 2026-11-12 批准连续开发。本文件是固件与电脑端共用的命令契约。当前支持单台已选设备；USB 和 Wi-Fi 身份相同。

2026-11-12实板更新：用户确认U12实际装配INA226并授权调整。0.1.1固定使用INA226；`device.info.measurement`公开芯片、20mΩ分流、电流步进125µA、电池电压步进1.25mV、128次平均及2116µs转换时间，`device.status.measurement.ina226_ready`表示身份与配置回读通过。没有自动回退至其他芯片驱动；0.1.0的`ina228_ready`不再作为当前状态字段。

## 板上充电循环（固件 0.1.3）

`charge.run` 参数为整数 `on_ms`、`off_ms` 和 `count`。单段 10～60000 ms，1～1000 次，合计最长 600000 ms。启动要求真实电池供电、主供电切换结束、充电已断开。受理时接通，走完接通段再断开，走完整个断开段才累计一次。最后保持断开。执行期间两个阶段都独占主供电与充电控制。控制客户端失联或写权到期时，板子继续完成已受理的有限次数。

按设备、启动和动作编号调用 `action.get` 可读出 `on`、`completed`、`count`、各段设置及单调毫秒时刻。运行中 `phase_start_ms` 表示当前段起点。各类完整段的板端实耗以 `min_on_ms/max_on_ms` 和 `min_off_ms/max_off_ms` 报告，零表示尚未观察到完整段。持有写权的客户端用 `charge.cancel`、目标 `action_id` 和独立请求编号取消，随即断开；取消时被截断的段不计入完整段统计。`action.cancel` 保持原有的按键取消语义。重连核对设备和启动身份后查原任务，结果未知时不重发。

验收目标为每个完整段 ±5 ms。200/500 ms 场景逐段核对 195～205 ms 和 495～505 ms，最终断开应持续到观察结束。2026-11-18 接线复测中，现场操作者确认充电输入端的两个时长都在该范围内。板上统计取自控制任务；本次未归档独立仪器的原始波形或实测极值。

## 信封与传输

请求：`{"v":1,"id":"请求编号","method":"device.info","params":{}}`。
写操作另外携带 `boot_id` 与 `controller`。HTTP 请求还需要 `Authorization: Bearer <设备令牌>`；USB 物理连接可读取 `network.status` 中的配对令牌。

成功响应：`{"v":1,"id":"请求编号","boot_id":"本次启动标识","ok":true,"result":{}}`。
失败响应的 `ok=false`，包含 `error:{code,message,details}`。结果未知不能当作操作未执行。

USB 帧：4 字节 ASCII `AMCU`＋4 字节小端 payload 长度＋UTF-8 JSON＋4 字节小端 IEEE CRC32（仅计算 payload）。单帧 payload 最多 32768 字节。解析器仅接受完整合法帧；启动杂字节不能作为业务响应。禁止自动改用另一协议。

Wi-Fi：`POST /rpc`，同一 JSON 信封。`GET /setup` 与 `POST /setup` 仅在人工配置热点期间可用；热点密码见使用说明。读写同一执行入口，HTTP 回调不直接操作 GPIO。

## 公共方法

| 方法 | 参数与行为 |
| --- | --- |
| device.info | 身份、固件版本、协议、能力及额定设计范围 |
| device.status | 控制状态、启动标识、状态版本、任务和模块健康 |
| control.claim | controller；接管需 takeover=true 和 expected_revision，且无在途动作 |
| control.renew | 更新当前 controller 活性；过期会话不能靠续约重新获得写权 |
| control.release | 显式释放写权，无在途动作；不改变输出 |
| power.select | source=off/battery/external；充电开启时只能保持 battery；异步返回 action_id |
| charge.set | enabled 布尔值；开启要求 battery 且没有供电切换 |
| keys.run | steps:[{mask:0..31,duration_ms:10..60000}]，repeat=1..1000；最多128步、总时长≤600000ms，结束释放按键 |
| action.get | action_id；queued/running/succeeded/cancelled/failed/unknown |
| action.cancel | action_id；仅可取消按键动作，取消请求与取消完成分别查询 |
| uart.configure | baudrate 属于 9600/19200/38400/57600/115200/230400/460800/921600；固定8N1，配置要求 TX 禁用 |
| uart.tx | enabled；禁用等待在途发送结束，最多5秒，失败返回 TX_NOT_DISABLED |
| uart.write | data_hex，最多4096字节；TX必须显式启用，返回发送结果，不代表对端处理成功 |
| telemetry.read | measurement_after、uart_after、event_after 为上次 next 值；返回三种独立序号数据、缺失和下一位置 |
| calibration.get | 获取六个通道校准；缺失明确为 uncalibrated，损坏为 invalid |
| calibration.set | channel、gain、offset、reference、min_value、max_value；线性换算值=名义值×gain+offset，写入NVS；不代表额定精度已验收 |
| timing.set | power_deadtime_ms=10..1000；出厂初值100ms，硬件待验证，禁止把初值当保证值 |
| network.status | 联网状态/IP/SSID；USB可取得设备访问令牌，HTTP不返回令牌 |
| network.configure | ssid、password，经明确操作保存并连接，不回传密码 |
| network.connect | 明确尝试连接已保存网络，不修改输出 |

## 写入与结果

请求编号1～64字符。固件保存最近64个变更请求及响应；同编号不同方法/参数拒绝。电脑端持久化请求编号与任务，缓存淘汰后不再保证固件去重；调用方不重放结果未知的动作。

设备写权60秒未续约后失效，保留占用者标识，输出保持，已接收动作完成。显式接管必须传回最新状态版本，且没有在途动作；旧控制者令牌随后失效。后台代表其运行实例持有设备写权，并独立管理网页/AI的操作权。

先断后通初值100ms是待实测工程参数，按键设置步进1ms不代表实际触点精度。所有状态是控制信号及执行记录；实际电气结果需要测量证据。

## 数据

测量通道：battery_v（V）、battery_i（A，正为向设备供电）、ain1～ain4（V）。每个样本带 `seq,boot_id,channel,value,nominal,unit,t_us,window_start_us,quality,calibration_revision`。时间是工具单调时钟，测量窗口标称估计与实际转换时间分别披露。无有效样本时 value=null，不补零。

UART 为原始字节的十六进制分块，使用累计字节偏移 `start,end` 和接收时间；硬件 FIFO 溢出数未知时单独报告 `hardware_overflow_events`。测量、UART、事件保留新数据，读取旧位置返回丢失范围；读取不消费共享数据。

未校准时 value 为明确标注的名义换算值，quality=uncalibrated；额定精度仅由独立验收报告证明。近零准确下限未确定，四路值不强制归零。工具不自动限流、断电、换源或重放写操作。

INA226读取0x01的16位有符号SHUNT和0x02的16位VBUS，名义换算分别为原始码×125µA和原始码×1.25mV，不读取未配置芯片CAL时恒为零的CURRENT寄存器。双通道平均名义周期541696µs；采样窗口按手册最大转换时间的两轮约1192ms估计，不代表同步采样或阶跃后必然稳定。电池通道校准记录版本由1改为2，旧INA228记录标为无效；四路ADS1115仍使用版本1。
