# 用户窗口DRC差异修复记录

日期：2026-11-04。主工程：`D:\LCEDA\projects\AI_TOOL\AI_TOOL.eprj3`。

## 问题与原因

用户在可见窗口手动检查出现错误。上一轮交付只对全新隐藏会话完成验收，遗漏了已经长期打开的用户窗口，这属于验证范围不足。

通过同一严格DRC接口直接复现原窗口3项错误：U4_41及相邻接地线的2项未连接，另有1项原理图/PCB网表不一致。磁盘PCB摘要与上一轮交付相同，可见窗口却比新隐藏会话多1条线。

逐项对比发现：

- 可见窗口残留导线`9a959dc5aece717f`，长约1.255µm，完全位于同网的U4_41焊盘铜内。删除该冗余图元后，两项接地连接报错消失，实际铜覆盖未减少。
- 原理图与PCB有119脚的自动网名不同，涉及39个自动编号；全部98组实际引脚连接集合相同。显式网名、检查规则、模组实体焊盘以及其它1682条线均一致。
- 因此不能把“磁盘文件未变、后台DRC为零”等同于当前用户窗口的检查也通过。

## 处置

原样重设第2页源码、通过`openProject`打开当前工程都未清除旧网名缓存。随后保存八页原理图与PCB，通过官方CLI结束旧会话，重新打开同一本地工程以重建编辑器状态。恢复八页标签页，最终停留PCB。

原生DRC检查脚本从3项错误变为0项；当前可见窗口的原理图和PCB完整415脚网名一致。没有改变检查规则。

为避免同一路径的并行编辑器会话干扰初始化，本轮把当前14份源文件逐文件复制并校验SHA256相同，在隔离目录的新隐藏会话复核。该会话的原理图及PCB DRC均为空，140颗器件、415个逻辑引脚、1682条线、192个过孔，网名逐脚一致，规则与修复前一致。此副本仅用于验收，主工程路径未改变。

另核对了修复前后有效源码中的器件、PAD_NET、铜线、过孔、覆铜边界、板框和禁布区，共2443条记录完全相同。源码规范化和缓存重建没有改动电路、布局及有效布线；删除的微小冗余线已被同网焊盘完全覆盖。
