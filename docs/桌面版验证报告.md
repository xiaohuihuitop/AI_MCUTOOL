Windows桌面安装器已构建并实际安装。正式安装目录为`C:/Users/admin/AppData/Local/MCU TOOL`，桌面和开始菜单均有 **MCU TOOL** 快捷方式。原0.1.2后台通过正常退出流程停止，正式桌面0.2.0已启动。

本机桌面配置明确沿用`D:/workspace/MCU_ESP/AI_MCUTOOL/.mcutool`与8766端口。最后检查时桌面会话在线，设备未连接、记录空闲、无人持有操作权；启动没有自动连接硬件或改变输出。

安装器包含Python后台及MCP运行程序、网页资源和微软签名有效的WebView2离线安装程序，不依赖用户另装Python、Node或Rust。安装器大小248,852,840字节（约237.32MiB），SHA256：


原生桌面流程逐项验证了：

1. 记录进行中拒绝停止后台。
2. 关闭窗口隐藏，并暂停整个页面脚本70秒；原生续约保持操作权在线，磁盘记录持续增加。
3. 重复启动恢复原窗口，后台实例不变。
4. 页面刷新复用同一个桌面会话。
5. 退出桌面端后，真实MCP观察者和后台记录继续。
6. 重新打开并明确接管、停止记录，通过Windows保存对话框下载有效的测量JSONL。
7. MCP仍在线时，停止后台被拒绝。
8. 通过Windows保存对话框导出有效诊断ZIP，核对文件白名单和版本；Python测试另行验证凭据及原始数据排除。
9. MCP明确分离后，停止后台并退出桌面，两进程实际结束。

## 证据与复现

正式证据位于[桌面版-0.2.0](软件验证证据/桌面版-0.2.0/)：Python、Rust及网页日志，桌面流程结果，冻结运行程序测试、安装卸载结果、快捷方式和正式运行摘要。测试页面截图持续带有“测试环境”标识。测试数据、授权文件、数据库和用户原始记录未复制到交付包。

开发构建入口为`scripts/build-desktop.ps1`，桌面交付入口为`scripts/package-desktop.ps1`。正式自动化测试位于`tests/test_desktop.py`、`tests/test_frozen_runtime.py`和`tests/desktop/`。执行原生测试前设置：

```powershell
$env:MCUTOOL_TEST_DESKTOP='实际安装目录/mcutool-desktop.exe'
$env:MCUTOOL_TEST_SERVICE='实际安装目录/runtime/MCUTOOL-service/MCUTOOL-service.exe'
$env:MCUTOOL_TEST_PWSH=(Get-Process -Id $PID).Path
node tests/desktop/smoke.mjs
```

测试会启动自己的隔离后台和测试设备，仅为自己的WebView2打开本机调试端口，结束后关闭测试进程。普通桌面启动不设置该调试端口。运行测试前先明确退出同一桌面实例，避免单实例规则将测试启动交给日常窗口。

构建工具为Rust 1.100.0、Tauri CLI 2.12.4、Tauri crate 2.12.5、PyInstaller 6.22.3、MSVC 14.44.35207和Windows SDK 10.0.26100.0。依赖锁文件与源代码一并保存。首次构建下载NSIS超时后，改从同一官方GitHub发布资产下载，并核对Tauri源码规定的SHA1；未修改产品的连接或错误处理行为。

本报告证明本机软件安装和已列出的行为通过验证，不替代不同Windows环境的兼容性测试、长时间压力测试或电气精度验收。工具板INA226的测量限制仍按[实板说明](INA226实板启动与测量限制.md)执行。
