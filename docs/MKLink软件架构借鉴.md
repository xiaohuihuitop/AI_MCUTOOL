# MKLink 软件架构借鉴

日期：2026-11-12。目标：参考 MKLink 的软件组织和使用方式，细化 MCU 开发辅助工具的软件设计。本文提出架构建议，不表示新增行为已经实现或全部确认。

## 1. 结论与依据

**本项目适合采用与 MKLink 相同的软件组织方式：使用 Skill＋MCP＋共享后台＋网页＋设备固件。** 两者都让人工和 AI 操作真实硬件，复用设备连接和观测数据。本项目的功能模块对应按键模拟、供电通路切换、充电器插拔模拟、测量和目标 UART。

本次读取用户指定 Skill、按需参考页及本地实现。按 Skill 要求执行了一次强制版本检查：本地完整包为 0.4.0，发布信息显示 0.4.3 可用；未安装更新。本次结论基于已读取的本地 0.4.0 实现，不把新版发布说明视为本机已有能力。未连接 MKLink、未启动其后台、未操作目标 MCU，也未验证其真实运行性能。

## 2. 对应的软件结构

| 部分 | MKLink 的职责 | 本项目的对应设计 |
| --- | --- | --- |
| 使用 Skill | 告诉 AI 如何发现设备、调用能力、处理占用和收尾 | 解释接线和额定条件、工具能力、测量含义、操作顺序和会话收尾；项目测试阈值仍在项目侧 |
| MCP | 把能力包装为 AI 可调用的工具 | 提供状态、按键、供电、充电、测量、UART 和记录调用；转交共享后台 |
| 共享后台 | 持有设备连接，协调客户端、采集和任务 | 统一管理 USB/Wi-Fi 连接、客户端、操作占用、动作记录、采样缓存和文件 |
| 网页 | 查看共享状态、手动控制和显示数据 | 保留已确认的简单操作面板；增加可展开的会话/任务状态，帮助解释“谁在操作”和“为什么被拒绝” |
| 设备固件 | 执行下载器协议和硬件能力 | 执行本地按键时序、供电互锁、INA228/ADS1115 采样及目标 UART 收发 |

Skill 是使用说明和调用规范；可执行能力由 MCP、后台和固件提供。后续交付需要配套程序、依赖和已构建网页资源，单独一份 SKILL.md 不能操作硬件。

本项目的软件保持独立设备身份和工具名称。AI 可以同时使用 MKLink 烧录/调试被测 MCU，再用本工具按键、切供电和测量，两个工具由项目侧 AI 编排。

## 3. 对现有草案的具体完善

### 3.1 共享的是运行状态，而不仅是代码

网页、MCP 和辅助命令行连接同一个后台实例。后台是日常设备通信的唯一持有者，负责公共缓存和状态；每个入口各自创建一套相同 Python 对象仍然会争用连接，不符合这一设计。

建议首版一个后台实例管理一块已选工具，先完成单设备使用。设备握手返回稳定 `device_id`，同一工具的 USB 与 Wi-Fi 返回相同身份；COM 号、IP 和显示别名都是定位信息，不作为设备身份。连接信息变化后需要重新核对身份，不能默选另一块板。

同一电脑按 `device_id` 防止创建重复持有者；已有后台则复用。后台不兼容时明确报错，不另开直接连接路径。跨电脑通过 Wi-Fi 竞争同一板子的写操作还需要固件端会话准入，本机进程锁不能解决这一问题。

### 3.2 把会话、操作和设备连接分开

建议分别管理四件事：

| 动作 | 明确含义 |
| --- | --- |
| 退出自己的会话 | 本客户端离开，不代替其他客户端停止记录，不取消板上已接收动作 |
| 停止记录 | 结束所选记录并保存结果，不等于关闭设备供电 |
| 断开设备通信 | 明确释放 USB/Wi-Fi 通信；不能表述为被测设备已断电 |
| 退出后台 | 明确结束电脑端运行；如何处理在途动作和未落盘数据应先检查并报告 |

网页关闭只结束页面订阅，已明确开始的电脑端记录继续运行；板上动作按已接受的参数完成。正常 AI 收尾退出自己的会话，不调用影响全局的断开或停止。

本项目已有“关闭网页不隐式停止记录”的设计，不套用 MKLink 的最后客户端离开后约 5 秒退出后台规则。程序空闲退出若以后确有需要，应单独定义触发条件和影响。

### 3.3 多人能看，写操作需要协调

观察者从共享缓存读取，各自维护读取位置。读取数据不会消耗另一客户端的数据，也不为读取而重启采集。

按键、供电和串口发送会影响同一个被测设备。建议增加显式的“操作占用”机制：一段 AI 测试取得写操作权后，网页仍可观察；人工想改变设备状态时先明确交接。手动单次操作也经过相同检查。该机制比单条命令排队更能避免“AI 测试到一半，被人工切换电源”。

占用者、正在执行的动作和拒绝原因在网页及 MCP 中可查。客户端失联、占用超时和人工接管条件仍需确认，不能自动抢占、取消未知结果的动作或重放旧命令。最终互锁仍在固件中执行，电脑端占用规则不能代替电气互锁。

### 3.4 操作必须能在超时后查询

建议按键序列和供电切换等有过程的动作由后台任务管理。调用先取得任务编号，后续查询结果；即时状态读取无需都包装成任务。

请求接受记录在向硬件发送前保存，包含请求编号、参数摘要、设备身份、启动标识和发起客户端。任务关联板上动作编号，并区分接收、执行、完成、拒绝、失败、取消及结果未知。

电脑端重启或回复丢失后，先用保存的编号和设备启动标识查询执行证据；证据不足保留“结果未知”，不重新执行来验证。任务历史和去重能力有容量/期限，过期查不到不能推断“没有执行过”。

MKLink 的任务通常在电脑端驱动烧录；本项目按键等定时动作在板上继续执行，所以必须关联“电脑端任务”和“板上动作”，不能仅以电脑协程结束作为完成依据。

### 3.5 采集、显示、记录分别运行

建议数据路线为：板上采集 → 后台批量接收 → 公共历史缓存 → 网页订阅、MCP 增量读取和记录器。

- 网页暂停绘图仅暂停显示；AI 仍可读取，已开启的记录继续写盘。
- 网页和 MCP 各有独立的读取位置；数据过期或超出缓存时返回实际缺失范围。
- 记录器直接接收后台数据，不依赖浏览器定时保存或页面显示的点数。
- 区分板上丢样、传输缺失、后台缓存覆盖、慢网页漏收及写盘失败；显示抽样不等于原始记录缺失。
- 原始记录保留采样时间和质量信息。历史查看只读取数据，不向硬件重放操作。

设备与后台之间继续使用既有 USB 帧/HTTP 批量读取设计。后台向网页可用 WebSocket 推送测量和串口块，普通操作用 HTTP；MCP 按序号读取后台缓存。这里是两段不同连接，不能因网页采用 WebSocket 就把固件通信方案一并改掉。

### 3.6 共用一份能力说明

参考 MKLink 的能力注册表，后台为每种操作集中定义名称、参数类型、范围、结果结构及资源要求。网页、MCP 和命令行调用同一模块；固件独立检查物理参数和互锁。

查询时分别返回软件支持的操作、固件实际能力、硬件设计范围、校准状态和经过验证的限制。不能仅看版本号猜测某能力可用，也不能把未校准读数包装成达到额定精度。

`runtime_status` 类查询应只查已有后台状态，不能为了查占用而连接设备、接通电源或创建新的写入会话。

## 4. 需要按本项目重新设计的部分

| MKLink 中的机制或功能 | 本项目处理方式及原因 |
| --- | --- |
| CDC 命令与部分调试采集互斥 | 本项目需要一边测量和收串口，一边按键或切供电；通过独立采集任务和短命令调度满足，不照搬“采集中不能操作” |
| 自动重连、恢复采集及旧协议路径 | 本项目已有显式选择连接、断网保持输出和不重放动作约定；本轮不新增自动恢复、切换或降级路径 |
| 探针输出 1.8/3.3/5V | 本工具选择外部供电通路，调压由外部电源承担；不能移植探针设定电压接口和参数 |
| 烧录、内存、RTT、符号、芯片型号目录 | 继续由 MKLink 等工具完成；不因软件形态类似而扩大本项目硬件功能 |
| 高速 SuperWatch 图表和微秒采样 | 本项目约 1Hz 稳定测量、四路顺序采样，趋势图必须反映自身数据能力 |
| Tauri 桌面壳、Site Agent、跨平台入口注册 | 当前已确认简单本地网页；这些可以后续独立评估，本轮不加入首版 |
| U 盘 HTML 启动入口 | 现有 ESP32 USB Serial/JTAG 不提供 MKLink 的磁盘形态；可在电脑提供启动入口，不为相似外观改变固件 USB 功能 |
| 5 秒会话/恢复窗口、64 个历史任务等数字 | 属于 MKLink 自身实现条件；本项目根据动作时长、内存、串口吞吐和验证结果定值 |

## 5. 技术建议与实现位置

据此把电脑端技术建议具体化为：**Python＋FastAPI 共享后台，FastMCP 作为 AI 入口，Vue 3＋TypeScript＋Vite 构建简单网页**；固件继续使用 ESP-IDF＋C。Vue 用于管理多区域共享状态与异步操作反馈，页面仍保持简单。该技术选择属于本次设计建议。

建议目录结构如下，尚未创建产品代码：

```text
firmware/             ESP-IDF 工程、本地执行和硬件驱动
host/                 共享后台、设备连接、任务/缓存/记录、MCP 和 CLI
web/                  状态和手动操作页面，构建产物由后台提供
protocol/             命令与数据契约、错误和版本约定
integrations/skill/   面向 AI 的使用入口及按需参考资料
tests/                软件接口和跨入口一致性测试
docs/                 设计、校准及硬件验收资料
```

关键验证是：网页与 MCP 共用连接和数据；重复请求不重复动作；AI 退出不停止其他使用者；页面暂停不影响记录；两种连接识别同一设备；板上时序不受网页/AI 阻塞；断网、后台重启与未知结果均可追踪。

本次把这些建议同步到[软件设计草案](MCU开发辅助工具软件设计草案.md)。使用 Skill 的正式内容等命令契约稳定后再编写，避免 AI 指南先于真实能力承诺功能。
