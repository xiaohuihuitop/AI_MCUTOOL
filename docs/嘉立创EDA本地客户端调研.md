# 嘉立创 EDA 本地客户端调研

调研日期：2026-10-26。范围：官方资料、现有插件源码及本机安装线索的只读核查；未安装客户端、切换模式或迁移工程。

**后续实测更新：** 用户安装客户端并提供 `D:\LCEDA\projects\AI_TOOL` 后，已用官方 CLI 4.1.78 在独立样例验证隐藏会话截图、文字修改、双向文件同步及关闭重开。用户原工程文件未改变，尚未迁移真实 MCU 工具设计。实测过程、接口异常和验证边界见[本地客户端实测](嘉立创本地客户端实测.md)。下文保留调研时点的结论。

## 结论

**建议本项目优先评估嘉立创 EDA 专业版桌面客户端的半离线模式，并选择 `.eprj3` 文件夹工程。** 用户已有立创使用习惯，半离线模式保留在线商城器件库，又让工程落在本地。相比本次浏览器加 easyeda-agent 的路径，官方新 CLI 提供了更直接的自动化入口。[1][2]

需要修正此前“立创只能依赖前台编辑器，不适合后台文件处理”的概括：官方现已明确提供 **V4.1.60 及以上客户端内置 CLI、隐藏渲染会话、MCP 和可直接读写的纯文本工程格式**。这些是已发布文档的功能，不是由“保存本地”推测出来的。[2]

但不能据此承诺本项目已经能无人值守截图。当前实际使用的是第三方 easyeda-agent，尚未把本工程接到官方 CLI；本机常见路径和卸载注册表未定位到专业版客户端。官方隐藏会话下，本项目 PCB 的真实出图与原有数据完整性仍需安装后的隔离验证。

## 三种运行模式

| 模式 | 工程和个人库 | 系统器件库 | 登录与协作 | 本项目建议 |
|---|---|---|---|---|
| 全在线 | 云端；可自动备份工程到本地 | 在线库 | 需要登录，支持协作 | 当前已有云工程可保留作迁移来源 |
| 半离线 | 本地 | 可以访问在线系统库 | 不需要登录，不支持协作 | **优先选用**，兼顾本地工程与选料 |
| 全离线 | 本地 | 不访问云端系统库；官方说明内置 1 万余常用库 | 不需要登录，不支持协作 | 适合隔离网络；本项目选新料时不如半离线方便 |

以上来自官方客户端常见问题。半离线允许访问云库，所以“工程保存本地”不等于客户端完全不联网；联网搜索和新增云端器件仍需要相应网络服务。本地库当前仅支持模糊搜索，不支持多条件搜索。[1]

安装桌面客户端本身不代表进入本地模式：客户端同样可以运行全在线模式，须核对实际运行模式。[1]

## 文件格式与云端迁移

| 格式 | 官方定义及适用方式 |
|---|---|
| `.epro` / `.epro2` | 工程导出、归档、交换格式；`.epro2` 是较新的工程归档格式，`.epro` 用于旧版格式兼容。当前项目已有 `.epro2` 导出物。[3][4] |
| `.eprj` / `.eprj2` | 客户端工程格式；新版 CLI 的 `open --path` 接受这些后缀。不能把它们自动当作可逐行评审的文本工程。[1][2] |
| `.eprj3` | 文件夹化工程，包含工程索引、`sch/`、`pcb/`、`panel/` 等；图页 `.esch2`、PCB `.epcb2`、面板 `.epan2` 为文本记录。官方支持直接编写，并提供 `doc format` 查询格式。[2] |
| `.elib` | 客户端本地器件库文件。[1][5] |

`.eprj3` 的编辑器保存会更新磁盘文件，磁盘文件变更也会被编辑器重新读取；这使脚本处理、Git 差异检查成为官方明确支持的用法。库文档内嵌于相应设计文件，不能只拷贝器件坐标而遗漏符号、封装、器件定义与引用。[2]

官方旧 FAQ 说明云端工程先导出，再到离线客户端导入；从离线返回云端同样需要导出工程包后导入。**切换运行模式并不代表同一份工程自动保持云地双向同步。** 新版更新记录还说明支持 `.epro/.epro2` 打开以及 `.eprj` 向 `.eprj3` 转换。实际迁移需保留唯一主工程，核对器件、网络、封装和布局后再确定工作来源。[1][4]

官方旧文件类型介绍尚未列全新版格式，因此不能仅凭旧 FAQ 认定只有 `.eprj`；本调研结合新版 CLI 文档和更新记录。[2][4][5]

## 官方后台自动化能力

官方 CLI 文档明确说明：[2]

- CLI 内置于 **V4.1.60 及以上**专业版桌面客户端，无需单独安装插件；浏览器在线版不支持该会话与桥接功能。
- `lceda-pro doctor` 检查本地桥接；`open`、`session list` 管理编辑器会话。
- `lceda-pro open --headless true` 可建立没有可见窗口的隐藏渲染会话。
- `invoke` 在会话中执行扩展 API；可用于读取、设计检查、导出及其他编辑器操作。
- 提供 `--mcp stdio` 和 HTTP MCP 入口。
- 提供 `.eprj3` 直接文件生成说明，包括 PCB 器件、网络、焊盘网络、板框和走线记录。
- 提供 PCB 原生画布截图及写入本地文件的代码示例。

**与 KiCad 能力有明显交集，但运行机制并不等同。** `.eprj3` 可以由外部程序直接读写；官方 CLI 的 DRC、导出、截图等仍以运行中的客户端编辑器会话为后端。隐藏渲染不代表完全不启动编辑器引擎，也不能由此承诺无 GPU、任意服务器环境或所有导出均已验证可用。[2]

官方客户端下载页面在本次读取时列出的专业版 Windows x64 安装包为 **4.1.78**，高于 CLI 文档要求的 4.1.60；本次没有下载安装。[6]

## 截图问题与现有插件

主代理核对现有 easyeda-agent 源码后确认：

- `extension/src/actions.ts` 的 `pcbSnapshot` 在 `pageVisibility() === "hidden"` 时直接拒绝。
- `extension/src/eda-context.ts` 的 `pageVisibility()` 读取 `window.document.visibilityState`，没有桌面客户端专用分支。
- 截图调用 `getCurrentRenderedAreaImage(tabId)`，取得当前画布渲染区域，并非直接解析 PCB 文件生成图片。
- 当前插件的工程导入路径依赖团队 UUID 与 `New Project`，没有实现本地目标目录分支；宣称可运行于 desktop/web，不等于已适配所有半离线工程操作。

这些是当前插件实现的限制，不能当成新版官方客户端能力的上限。

Electron 官方说明：Windows/Linux 下窗口只是被其他窗口遮挡时，通常不会使页面 visibility 变为 hidden；最小化或显式隐藏才会。macOS 还跟踪遮挡；后台节流设置也会影响此行为。因此普通桌面窗口保持不最小化，理论上可能减少聊天切换造成的截图失败，但嘉立创具体窗口配置和内部标签页仍需实测。[7]

更值得评估的是官方 CLI 的 **hidden render** 路径，而非简单取消插件的可见性检查。官方虽同时给出了隐藏会话和 PCB 截图能力，本文没有把二者组合到本项目上运行，故尚不宣称问题已解决。[2]

## 扩展与本地文件权限

官方支持扩展广场联网安装，也支持导入 `.eext` 扩展包；涉及联网等外部交互时，需要启用外部交互权限。[8]

官方扩展类型声明提供 `isClient`、`isOnlineMode`、`isHalfOfflineMode`、`isOfflineMode`。客户端专用的 `readFileFromFileSystem`、`saveFileToFileSystem`、`listFilesOfFileSystem` 要求外部交互权限；`getProjectsPaths` 仅半离线/全离线模式有意义。官方 CLI 文档将文件接口可用范围与配置的工程目录相联系。[2]

本地文件模式不会自动修复 easyeda-agent 的多单元处理和写入验证问题；采用官方 CLI 或 `.eprj3` 是另一条实现路径，仍须在本项目上核对保存重载、网络一致性、DRC 和实际图面。

## 推荐的下一步验证

若用户决定试用桌面客户端，先用独立临时工程验证下列项目，再迁移主工程：

1. 核对版本、运行模式、官方 CLI 帮助与 `doctor`。
2. 半离线模式创建 `.eprj3`，核对本地文件与云端系统库查询。
3. 在隐藏会话中读取 PCB、执行检查、导出新鲜截图，确认切回聊天时仍正常。
4. 导入已有 `.epro2`，对比 164 个器件、508 个逻辑脚及网络、封装与布局；本项目仍是未布线稿，不能把未连接项当作迁移失败或直接宣称制造检查通过。

本次只做研究，没有执行上述安装、模式切换或工程迁移。
