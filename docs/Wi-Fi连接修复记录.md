# Wi-Fi 连接修复记录

日期：2026-11-12。电脑端和网页版本：0.1.2。工具板固件保持0.1.1。

## 问题与原因

工具板已联网并获得192.168.1.62地址，用户在网页选择Wi-Fi连接时遇到`UnsupportedProtocol`。实际输入为以一个空格开头的HTTP地址。

原代码用Python的`urlsplit`校验地址。该解析器忽略前导空格，因此校验通过；随后HTTPX却收到带空格的原始地址，将其视为缺少HTTP协议的相对地址，在发出网络请求前报错。使用真实本地HTTP服务复现时，同一地址不带空格通过，加一个前导空格即失败。

## 修复结果

网页、共享后台、HTTP传输和MCP复用比较现在采用一致的地址处理：去掉首尾空白与可选根斜杠，再使用同一地址进行校验和请求。内部空白、缺失协议或不支持的协议仍明确拒绝；没有自动补协议、切换通道或重放动作。

已重启电脑端后台加载修复，通过用户提供的设备地址和访问令牌连接真实工具板。共享状态确认：

- 电脑端版本0.1.2，连接方式HTTP，地址`http://192.168.1.62`。
- 设备身份`MCUTOOL-68EE8F59EE9C`，固件0.1.1，非测试设备。
- 六路采样持续有效，连续状态检查期间启动标识不变，运行时间递增。
- MCP使用带首尾空白和根斜杠的同一地址成功复用连接，退出MCP会话后连接保持。

验证过程中未申请硬件操作权，未发送供电、充电、按键或UART控制命令。没有修改或重新烧录工具板固件。访问令牌不写入本记录或验证文件。
