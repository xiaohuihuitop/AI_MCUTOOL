# MCU TOOL 首版软件使用说明

适用版本：桌面、电脑端及网页0.3.0、工具板固件0.1.1，Windows本地共享后台。固件目标 ESP32-S3-WROOM-1-N16R8，电池测量按用户确认的实装INA226。软件编译、实板启动检查与电气/精度验收分别记录，实际硬件范围以项目最终验收为准。

## 1. 启动软件

日常使用可安装Windows桌面版并双击 **MCU TOOL**，详见[桌面版使用说明](桌面版使用说明.md)。本次工作区也已安装项目依赖并构建网页；双击根目录 **启动工具.cmd** 可打开本机网页操作面板。启动只运行电脑端后台，不自动连接设备或开启输出。再次启动复用同一后台。

复制工程到另一目录或电脑后，先安装 Python 3.11、Node.js 22，以及用于开发辅助脚本的 PowerShell 7，在项目目录执行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/install.ps1
```

上述源码依赖来自 `requirements.lock.txt` 与 `web/package-lock.json`，首次安装需要网络。桌面安装器已随附独立运行环境，无须执行上述开发安装步骤。后台默认 `http://127.0.0.1:8766`，仅本机可访问；端口占用时明确报错，不自动改端口或另开独占设备连接。

日常双击启动入口直接调用项目Python，不依赖PowerShell。本文其余 `.ps1` 命令在PowerShell 7中执行，符合项目UTF-8无BOM编码约定。

需要指定端口或仅启动后台时：

```powershell
./scripts/start.ps1 -Port 8766 -NoBrowser
```

## 2. 工具固件

本次软件包在工作区 `release/` 的版本目录中；解压后固件、bootloader、分区表和下载参数位于 `firmware/build/`，包根目录的 `manifest.json` 记录SHA256清单。源码位于 `firmware/`。

本机重新编译：

```powershell
./scripts/build-firmware.ps1
```

默认使用现有 ESP-IDF 5.4.4，位置为 `D:\esp\.espressif\v5.4.4\esp-idf`；工具位于 `C:\Espressif\tools`。脚本只配置当前进程，可用 `-IdfRoot`、`-ToolsRoot` 指定相同版本安装位置。

烧录必须明确指定本工具的原生USB端口，不能把其他下载器串口当作工具板。本次没有自动烧录任何端口。手动下载可用：

```powershell
./scripts/flash-firmware.ps1 -Port COM实际编号
```

该脚本只接受枚举为乐鑫原生USB的明确端口，并由esptool继续校验ESP32-S3芯片。若固件尚不能枚举，按住BOOT，按下并释放RESET，再释放BOOT，重新确认端口后下载。USB接电脑时不同时接DC；开始实物测试前检查外部接线及电气条件。

上电/重启后按键、主供电和充电关闭，TX高阻。上电至初始化前及各类复位期间的实际引脚表现仍待实测。

## 3. 连接与操作权

在“连接设置”选择USB并明确端口，或选择Wi-Fi填写设备地址和访问令牌。连接后核对设备身份。相同工具的USB和Wi-Fi身份一致；改变连接方式需要明确断开并重新连接，没有自动切换。

Wi-Fi地址使用完整HTTP地址，例如`http://192.168.1.62`。0.1.2会去掉复制时带入的首尾空白，不会自动补协议；本次实板Wi-Fi连接已验证，见[修复记录](Wi-Fi连接修复记录.md)。

网页与AI共用后台。所有客户端都能观察；修改设备前点击“申请操作权”。其他操作者持有时，需要核对原流程是否允许交接，再明确“接管操作权”。有在途动作或状态版本变化时接管会被拒绝。

客户端60秒未续约标为离线，不自动转交写权，不改变供电或充电，已接受的按键动作正常结束。网页刷新后的新会话可根据状态显式接管；桌面刷新页面复用原生进程维护的同一会话，隐藏窗口仍持续续约。后台与设备的操作权分开校验。

“断开设备通信”只释放通信连接，不代表设备已经断电。“释放操作权”也不改变输出。普通AI收尾使用 `detach`，避免打断共享使用者。

## 4. 主要操作

0.3.0 使用浅色工作台，新增独立“操作记录”“四路电压”页面，以及双轴电池图、游标统计和每通道显示设置，详见[界面与图表使用说明](上位机界面与图表使用说明.md)。

| 区域 | 用法和结果含义 |
| --- | --- |
| 供电与充电 | 选择关闭/真实电池/外部电源。充电开启时必须先关充电，才可切外部电源或关主供电。状态表示控制命令，实际电气结果看测量 |
| 按键 | 每路可单击；选择多个K1～K5，设置按下、释放时间和次数，可组合或连击；长按直接设置时长。取消只释放该动作按键 |
| 测量 | 显示电池接口电压、电池端双向电流、四路外部电压，附校准和过期状态。没有数据时显示“未读取”，不显示假零值 |
| 趋势 | 按采样时间显示，缺口断开；“暂停显示”不停止后台采集与记录 |
| 目标串口 | 固定3.3V TTL、8N1、无RTS/CTS；禁TX后配置波特率，显式启用后发送文本或HEX；不自动追加换行。设备掉电前先禁TX并确认完成 |
| 操作与事件 | 查看人工/AI来源、任务编号、执行进度、拒绝原因及连接/缺失事件。已受理不等于已完成，已完成不等于被测设备行为通过 |

主通路设计目标2.8～12V/双向3A；独立充电5V/2A；五路触点≤6V/20mA；外部电压检测0～15V。量程、开关能力与实际精度是不同概念。电流正方向为经分流器向设备供电，不是充电器输入电流。

## 5. 记录与导出

在“串口与记录”明确点击开始记录。原始记录位于所配置数据目录的`recordings/`，本机沿用项目`.mcutool/recordings/`；全新桌面安装默认位于`%LOCALAPPDATA%/MCU_TOOL/data/recordings/`：

- `会话.json`：开始时的设备、连接、校准、软件版本及最终记录状态。
- `测量.jsonl`：逐份采样时间、数值、单位、质量、设备/启动标识。
- `事件.jsonl`：操作及数据缺失事件。
- `串口.bin` 与 `串口索引.jsonl`：原始字节及其位置、时间、设备/启动身份，配套分析。

停止后检查状态，再展开已有记录下载文件。关闭网页和AI退出会话不会停止已经开始的记录。记录目录不可写、队列溢出或写盘失败会显示失败/不完整，保留已写文件。

原操作者已离线、无在途动作时，其他有效客户端可核对当前后台状态并点击“确认停止无人记录”；此操作只结束本机文件记录，不取得设备写权。正常情况下由当前操作者停止记录。

同一设备、同一次启动重连继续原读取位置；断网超过板上缓存容量时报告缺失。设备重启或更换形成新数据段，无法恢复的旧缓存明确记录。图表点数、网页漏收和磁盘记录完整性分别判断。

## 6. Wi-Fi 与校准

首次可以通过USB连接，在“设备设置”保存SSID和密码。板上无配网记录时会开启 `MCUTOOL-xxxxxx` 热点；人工长按CONFIG三秒也可开启。热点密码 `mcutool-setup`，连接后访问 `http://192.168.4.1/setup`。成功联网后热点关闭；正常失联不自动开启热点或循环重连，可通过USB明确连接已保存网络。

设备IP从USB网络状态或路由器获得，Wi-Fi访问令牌从USB设备设置或配网页面获得。设备密码不进入普通任务日志；`.mcutool/runtime.json` 含本机后台授权，不要分享。

六个测量通道分别校准。稳定输入下取得两组名义读数x1/x2与参考值y1/y2，计算增益 `(y2-y1)/(x2-x1)` 和偏移 `y1-增益*x1`；电流单位A，电压单位V。填写已验证范围和参考仪表/温度等条件，再保存对应通道。用其他独立点验收精度；近零饱和和非线性不能靠固定偏移修复。

当前INA226＋20mΩ分流器的电流读数步进为125µA（0.125mA），电池接口电压步进1.25mV。芯片手册规定条件下，未校准分流输入失调上限±10µV折合±500µA；这不是校准后的整机误差承诺。原INA228方案的小电流±100µA目标不能直接沿用，需用实际参考仪表重新评估。旧INA228电池通道校准记录会标为无效，需要重新校准；四路ADS1115记录格式保持。详见[实板检查与测量限制](INA226实板启动与测量限制.md)。

未校准时显示明确标注的名义换算值；损坏记录标为无效，不自动替换系数。供电先断后通100ms为待实测工程初值，“设备设置”可调整本次启动参数，重启恢复初值。

## 7. AI 接入

合并 `integrations/mcp.example.json` 中的mcutool条目到AI客户端支持的配置位置，保留其他工具；移动工程时修改其中两个绝对路径。配套 Skill 位于 `integrations/skill/mcu-assistant-tool/`，可显式引用或安装到客户端支持的Skill目录。

通常顺序：`ping → connect → device_status → claim_control → 操作与job_status → recording/status → release_control → detach`。按具体任务决定是否记录和何时释放，任务结果未知时使用查询证据，不重发原动作。本工具不控制外部电源调压，也不烧录被测MCU；这些仍由相应工具提供。

## 8. 后台退出与故障定位

在“设备设置”内展开“后台与客户端”可查看共享使用者。需要退出程序时，先停止记录、等待动作结束，再点击“退出后台”。其他客户端仍在线时拒绝退出；关闭页面的活性登记最多60秒后过期。退出不改变板上输出。

命令行只读查询与显式退出：

```powershell
.venv/Scripts/python.exe -m mcutool.cli status --data-dir .mcutool
.venv/Scripts/python.exe -m mcutool.cli job --data-dir .mcutool --request-id 先前保存的编号
.venv/Scripts/python.exe -m mcutool.cli stop --data-dir .mcutool
```

通信超时先查询任务和设备状态，不能据超时断定没执行。后台重启将未完成任务保留为未知；有板上动作编号且身份/启动匹配时可用 `job_reconcile` 取证，没有证据则保持未知。

启动错误看 `.mcutool/runtime.log`。不要清除活跃锁、结束所有Python进程或把另一台设备当作恢复目标。数据和错误有明确状态，软件没有自动改协议、换通道、限流、关断或换源逻辑。

## 9. 实物验收

2026-11-12已在用户确认仅接USB的工具板上完成首次烧录和启动检查。首次下载端口COM40，设备身份为MCUTOOL-68EE8F59EE9C；换USB口或电脑后仍需重新核对端口。当前已接入共享后台，不代表精度或全部电气性能通过。仍需验证启动/复位全过程引脚状态、Wi-Fi实际联网、按键物理时序、MOS互锁/压降/温升、双向电流和四路电压校准、UART速率/高阻/反灌。具体结果见[实板检查与测量限制](INA226实板启动与测量限制.md)。
