# MCU TOOL Windows桌面版

适用版本：桌面、共享后台和网页1.0.0；工具板固件0.1.4。六路固定10Hz，电池与四路电压各自支持开始/暂停、清空、CSV导出和最近4小时波形，详见[图表说明](上位机界面与图表使用说明.md)。随安装包提供运行环境，日常使用及MCP接入不需要安装Python或Node.js。

## 安装与打开

从 0.5.5 起，启动后会匿名检查并预下载更新，工作台顶部显示目标版本和下载进度。验签通过后可点“立即安装”，也可点“稍后”，再从“查看已下载更新”打开。断网时仍可安装已下载并验签的工具包。安装前会重新验证缓存，并检查共享后台的任务、记录和其他客户端。0.5.1～0.5.4 用户可从托盘“检查更新”选择“更新并重启”，0.6.0-rc.1、0.5.0 及更早版本需要先手动安装 1.0.0。

发布签名由 GitHub Actions 的 `desktop-release` 环境保管，部署分支限于 `master`。桌面内嵌 `desktop/src-tauri/tauri.conf.json` 中的公钥。本机构建后将实际安装器摘要写入 `integrations/desktop-release.json`，提交到 `master`。以该提交的完整 SHA 为目标创建正式版草稿并上传安装器，在同一提交上手动运行 `Sign desktop update`。工作流核对草稿、版本及安装器 SHA256，签名中绑定版本，并上传同名 `.exe.sig`。发布前用客户端公钥核验签名，发布后匿名复验安装器和签名。正式更新的私钥仅作为该环境的 secret 提供给签名步骤。

工具板固件使用独立的 Ed25519 密钥。维护者将已发布的固件 ZIP、SHA256、芯片和硬件修订填入 `integrations/firmware-release.json`，在 `master` 上运行 `Sign firmware release`。工作流核对实际下载文件，使用 `firmware-release` 受保护环境签署清单，产物名为 `firmware-release-signature`。

在对应提交上取出产物内的 `firmware-release.json.sig`，运行 `.venv/Scripts/python.exe scripts/prepare-firmware-update.py <签名文件> <正式固件ZIP>`。脚本用仓库固件公钥验签，核对包摘要和 ESP 镜像头，再生成 `integrations/firmware-update.json`。该文件将原始清单字节和签名一起发布。配套固件 0.1.4 适用于标记为 `2026-11-10` 的 ESP32-S3 工具板。

从[GitHub Release](https://github.com/xiaohuihuitop/AI_MCUTOOL/releases/tag/v1.0.0)下载安装器，或在取得的仓库中运行`powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/setup-desktop.ps1 -Auth Anonymous -Launch`自动下载、校验和安装。AI接入见根目录README。开发机的`release/latest-desktop.json`只索引本地打包结果，克隆仓库不会带上该目录。

安装到当前Windows用户，创建桌面和开始菜单中的 **MCU TOOL** 快捷方式。安装器包含WebView2离线安装程序；已有满足要求的WebView2时沿用现有运行环境。

双击快捷方式打开工作台。再次双击只显示已有窗口，不另开设备连接。软件启动不会自动连接工具板或改变输出；在连接设置中明确选择USB或Wi-Fi，再申请操作权。

本机已配置为沿用项目的`D:/workspace/MCU_ESP/AI_MCUTOOL/.mcutool`数据目录，与原项目MCP共用后台和历史记录。其他电脑默认使用`%LOCALAPPDATA%/MCU_TOOL/data`。配置文件位于`%LOCALAPPDATA%/MCU_TOOL/desktop.json`，内容如下；更改前先正常退出当前后台和桌面：

```json
{
  "data_dir": "D:/workspace/MCU_ESP/AI_MCUTOOL/.mcutool",
  "port": 5210
}
```

数据目录须为绝对路径。端口被其他程序占用、已有后台版本不同或配置有误时，程序明确提示，不另找目录或端口。原有网页版仍可通过`http://127.0.0.1:5210/`使用。

## 关闭窗口和退出

“连接设置”显示实际连接的串口或 Wi-Fi 地址。点“断开连接”会释放整台工作台共用的通信，其他网页和 MCP 会同时看到断开。断开前先完成在途动作，并由持有操作权的客户端执行。板上电源、充电和按键保持当前状态。

0.5.4 会在停止共享后台之前检查安装目录是否还有 MCP 进程占用。遇到占用时按提示正常退出对应客户端，再检查更新。若后台已停止而安装器启动失败，桌面会恢复同版本后台和会话，设备由用户重新选择连接。从 0.5.1 升级时，应先正常退出相应 MCP；若旧版已报错，从托盘选择“退出桌面端（后台继续运行）”，确认共享后台已正常停止后运行新版安装包。

| 操作 | 结果 |
| --- | --- |
| 点窗口右上角关闭 | 隐藏到托盘，桌面会话仍在线，采集与记录继续 |
| 点击托盘图标或再次打开快捷方式 | 显示原窗口 |
| 仅退出桌面端 | 分离桌面会话；共享后台、AI会话和已开始的记录继续 |
| 停止后台并退出 | 先检查记录、在途任务和其他客户端；条件允许时停止后台并退出窗口 |

托盘右键也提供显示、诊断导出和两种退出操作。退出界面或后台均不表示设备已经断电，也不会取消已经接受的板上动作。要关闭输出，应在仍连接设备时明确操作并核对结果。

桌面通过原生线程维持会话，隐藏窗口不依赖网页计时器。仅退出桌面后，原操作权不会自动转交；重新打开后根据实际状态明确申请或接管。后台连接异常会提示错误，需要用户明确重新打开，不自动重连或重发硬件命令。

## 日志与记录

界面布局和图表操作见[上位机界面与图表使用说明](上位机界面与图表使用说明.md)。“操作记录”“四路电压”现为独立页面。

在「操作记录」上方可查看工具板最近确认的供电、充电和按键状态。以元件面俯视，USB-C 和 DC 5V 在左，右侧五个按键接口从上到下为 KEY1、KEY2、KEY3、KEY4、KEY5，已与交付实板核对。触片搭接表示闭合，抬起表示释放，问号表示状态未知。板端状态约每 0.5 秒刷新一次，短按可能在两次刷新之间完成。

在“设备设置 → 后台与客户端”或托盘菜单中选择“导出诊断日志”，选择ZIP保存位置。诊断包包含运行状态摘要及有限长度的脱敏日志，排除访问令牌、密码、原始串口数据和完整测量记录。

在“串口与记录”停止记录后展开记录项，点击所需文件，通过Windows保存对话框另存。完整记录仍在所配置数据目录的`recordings/`内；诊断ZIP不代替原始记录。

不要分享数据目录的`runtime.json`；它含本机后台授权信息。设备操作、记录含义和INA226测量限制见[软件使用说明](软件使用说明.md)。

## MCP接入

安装包中的`runtime/MCUTOOL-service/MCUTOOL-service.exe`既是后台程序，也是stdio MCP入口。按实际安装位置修改[安装版MCP配置示例](../integrations/mcp.desktop.example.json)，再合并到AI客户端配置；程序不会自动修改其他工具配置。

其中`--data-dir`必须与桌面配置相同。桌面和AI共享一个后台，由操作权规则决定谁可以修改设备；AI观察和调用不需要桌面窗口一直打开。已有项目Python方式的MCP配置可以继续使用，但项目代码和运行后台须为同一版本。

## 升级与卸载

先结束记录、等待动作完成，让其他AI客户端退出本工具会话，再选择“停止后台并退出”。之后运行新安装器，或在Windows“已安装的应用”中卸载MCU TOOL。

后台或MCP仍使用安装目录时，卸载会拒绝继续。卸载保留用户数据目录和桌面配置；安装包不包含个人记录或设备授权。当前构建未配置发布者代码签名。

## 从源码构建

源码构建需要Python 3.11、Node.js 22、Rust 1.100.0，以及Visual Studio 2022 C++ Build Tools和Windows SDK。运行环境版本由`requirements.lock.txt`、`desktop/requirements-build.txt`、两个`package-lock.json`及`desktop/src-tauri/Cargo.lock`记录。

在项目根目录的PowerShell 7中执行：

```powershell
./scripts/install.ps1
.venv/Scripts/python.exe -m pip install -r desktop/requirements-build.txt
npm.cmd ci --prefix desktop
./scripts/build-desktop.ps1
```

`-NoInstaller`只构建可运行桌面目录；`-SkipService`仅用于明确已经重新打包过后台的开发迭代。构建不会烧录工具板。交付前需执行Python测试、网页端到端测试、冻结后台测试和`tests/desktop/smoke.mjs`的实际Windows窗口验证，结果见[桌面版验证报告](桌面版验证报告.md)。
