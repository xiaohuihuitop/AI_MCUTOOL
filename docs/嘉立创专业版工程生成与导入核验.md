# 嘉立创专业版工程生成与导入核验

核验日期：2026-10-23。**执行现状：已在用户授权并登录的网页版V4.1.78建立八页原理图，保存、重开及网表检查已完成，原生工程已导出。** 实际结果见[原生工程交付与检查说明](原生工程交付与检查说明.md)。下文的客户端调查、未执行事项及入口辨别保留为早期资料研究记录，不代表当前仍在等待安装或登录。

## 结论

**后续推进已改为用户授权的浏览器专业版，当前优先使用正式“运行脚本”入口，无需先安装自定义扩展。** 官方说明V3入口为“高级→运行脚本”，脚本会得到独立的`eda`对象；当前会话已由主任务打开浏览器专业版并观察到V4.1.78，登录及具体API可用性以该会话实际结果为准。以下“助手内嵌”和独立客户端部分保留为早期环境辨别，不能当作当前必须安装客户端的要求。[S12]

**用户实际使用“嘉立创下单小助手”内嵌的EDA专业版，不能直接等同于独立专业版桌面客户端。** 本任务环境信息显示助手安装在`D:\Application\嘉立创\install`，程序为`jlc-assistant.exe`、助手版本5.1.25，尚未找到独立`lceda-pro.exe`；助手版本号不能当作内嵌EDA的版本号。

已核实的原生自动化路径是**独立嘉立创专业版桌面客户端的CLI与扩展API**，要求客户端V4.1.60及以上；当前下载页列出的Windows x64专业版为**4.1.78**。它能在激活后的半离线模式创建本地`.eprj3`工程，不要求登录使用，同时允许搜索云端系统器件库。但本次没有官方证据证明`jlc-assistant.exe`也实现此CLI，不向助手程序直接套用`doctor/open/invoke`命令。[S1、S2、S3]

不应在没有客户端、库样本和格式参考时，凭字段猜测手造`.epro`或`.esch`并宣称可导入。官方直接写文本工程的流程也要求先通过编辑器API创建骨架、取得真实库文档，再写业务记录，最后回到编辑器检查对象数量、网表、DRC和图片。[S1]

## 助手内嵌EDA的当前路径

本次读取的专业版官方导入、扩展及客户端文档均未明确列出“下单小助手内嵌版本”的支持矩阵。因此以下是需要在用户实际编辑器核对的入口，而不是已验证可用的功能：

1. 打开助手内的EDA后，在“关于”或编辑器标题中核对**EDA自身版本**及运行模式。
2. 核对“文件→导入→嘉立创EDA（专业版）”是否存在。官方专业版说明该入口接收`.epro`或工程`.zip`；只有内嵌环境实际成功导入后才能确认本任务交付路径。[S5]
3. 核对“高级→扩展管理器→导入”是否存在。官方V3编辑器支持导入`.eext`扩展；V2的路径为“设置→扩展→扩展管理器”。扩展API是在编辑器前端运行的JavaScript接口，不等同于本地CLI桥接。[S11]
4. 若内嵌环境有扩展管理器且所需API可用，可以在编辑器内通过扩展创建原理图，再使用“工程另存为本地”输出专业版工程包。需验证API版本、库搜索、创建/保存及导出能力，不能仅见到扩展菜单就认定整条链路通过。

目前没有证据证明助手内嵌环境能直接打开`.eprj3`本地目录工程，也没有证据证明它使用独立客户端的激活流程。独立客户端的最低版本、安装和激活信息只描述可选的独立工具路径，不要求用户先更换现有助手。

## 格式与用途

| 格式 | 已核实用途 | 本项目建议 |
| --- | --- | --- |
| `.eprj3` | 客户端半离线/全离线的文件夹＋多文件工程格式，JSON文本，支持编辑器与磁盘双向同步 | 作为本地工作工程；项目目录内包含工程索引和原理图、PCB等子文件 |
| `.esch2` | `.eprj3`中的原理图源文件；可在同一文件嵌入多个SYMBOL、FOOTPRINT、DEVICE、BLOB及SCH_PAGE文档 | 由编辑器生成库内容；只按查询到的格式规范编写或修改页面业务记录 |
| `.eprj2` | 单文件SQLite工程格式 | 可以由编辑器使用，但不作为本次优先的文本生成格式 |
| `.epro`或工程`.zip` | 官方导入页面明确支持的专业版工程交换包；从编辑器“工程另存为本地”获得，包含工程使用的器件和封装 | 需要交付给其他专业版环境时由编辑器导出，不仅压缩几份Markdown或网表后改后缀 |
| `.epro2` | 新版`SYS_FileManager.getProjectFile()`支持的另一导出格式，参数为`'epro' \| 'epro2'` | 按接收方版本选择，并实际重导入验证；不假定旧版全部兼容 |
| `.elibz`、`.esym`、`.efoo`等 | 专业版器件库包及符号/封装交换格式 | 用于分发库；不能代替完整工程 |

`.eprj3`的`fileFormat`参数只在客户端半离线或全离线创建工程时生效，在线环境会忽略它。官方旧FAQ中的`.eprj`叙述不能作为最新文本格式规范。[S4、S5、S6、S7]

官方给出的典型文件布局为：[S1]

```text
项目目录/
├─ 项目名.eprj3
├─ sch/
│  └─ 原理图名/
│     ├─ 原理图名.ecfg
│     └─ P1.esch2
├─ pcb/
│  └─ PCB1.epcb2
└─ panel/
   └─ Panel1.epan2
```

这些文件的存在取决于实际创建的文档，不应预先伪造空白PCB或面板来凑齐目录。

## 最小生成与验证流程

1. 定位用户现有`lceda-pro.exe`，先运行`--help`确认版本，再运行`doctor`检查`ok`和`value.connected`。客户端未启动时`connected:false`不等同于安装损坏。[S1]
2. 使用半离线模式，在工具配置允许的本地工程目录中创建本任务的新工程。`SYS_FileSystem.getProjectsPaths()`可读取允许的工程根目录；不需要读取账号、令牌或Cookie。[S1]
3. 使用`open --headless true`创建自动化会话，取得真实`sessionId`。不借用或关闭用户已有会话。使用当前版本帮助确认调用参数，关键调用保存返回JSON。[S1]
4. 通过`eda.dmt_Project.createProject(..., EDMT_ProjectFileFormat.EPRJ3)`创建工程，检查UUID不是`undefined`，再`openProject()`并等待就绪。工程名参数仅允许字母、数字和连字符；项目现有`AI_MCUTOOL`若直接作为该参数会包含不允许的下划线，需按工具限制选定名称。[S9]
5. 显式创建原理图并回读页面信息。`createSchematic(boardName?)`和`createSchematicPage(schematicUuid)`均有官方接口；页名用`modifySchematicPageName()`修改。[S10]
6. 使用`LIB_Device.search()`查询精确料号，核对实际返回的器件、封装和管脚，再经`SCH_PrimitiveComponent.create()`放置。创建后回读属性，再用`modify()`设置位号和属性。库UUID、器件UUID、封装UUID均来自实际查询，不填样例中的随机值。[S1]
7. 用`getAllPinsByPrimitiveId()`取得放置后绝对管脚坐标；按读回坐标创建正交导线和网络标识。不能仅按芯片原始引脚号推算符号坐标。[S1]
8. `sch_Document.save()`后等待拓扑刷新；导出并检查器件数量、引脚连接网表、BOM、DRC结果和每页图片。官方建议批量20～25颗放置、变更后等待5～10秒再查询。[S1]
9. 需要交换包时调用`SYS_FileManager.getProjectFile()`导出，并检查真实磁盘产物；仍需在目标版本重新导入验证。该接口要求“工程管理→下载工程”权限；应使用当前允许的权限，不能把权限错误忽略成导出成功。[S6]
10. 自动化会话不再需要时用`session close --session <实际ID> --destroy`关闭该会话。最终明确哪些检查完成，哪些电气/样机问题仍待验证。[S1]

这里列出接口和顺序，不声称这些步骤已经在本机执行。

## 官方文档的不一致与使用原则

当前官方CLI教程的建工程示例在`createProject()`之后直接读取`p.data[0]`中的Board和第一页；但最新`DMT_Project.createProject()`参考明确说明：**新建工程不初始化任何文档，需显式创建schematic/pcb/board**。实施时应以当前安装版本的API帮助和实际返回值为准，创建后检查状态，不依赖教程中的默认Board假设。[S1、S9]

`createSchematic()`参考中参数说明/示例称“不传boardName得到游离原理图”，备注又说明“不传boardName会自动创建Board”。因此不能盲目再调用`createBoard()`，避免生成两块板；应在调用后回读Board和原理图归属。[S10]

以上差异无需扩大到私有格式逆向，使用已公开API和回读验证即可控制。

## 无客户端时可完成与不能宣称完成的工作

可在普通文件工具中整理器件清单、管脚网络连接、页面布局计划和生成脚本；取得真实`.eprj3`种子及完整格式参考后，也可离线对已有文本进行静态检查。

但当前没有客户端和真实库导出，无法运行`doc format`、采集器件库、核对符号实际管脚坐标、执行编辑器DRC或验证原生导入。官方未在本轮查到的公开页面中提供无需编辑器即可使用的完整最小工程包；`.epro`内部容器规范也不能从“ZIP可以导入”这一事实反推出。不能把CSV、JSON连接表或SVG示意图称为已经通过导入的嘉立创原理图工程。

官方明确支持直接写`.eprj3`文本，但要求从编辑器取得工程索引和库文档。`.esch2`按行组织，外壳和载荷以`||`分隔，行末为`|`＋LF；页面组件的`partId`须指向真实符号的`PART`记录，ID与ticket须满足唯一性。这些规则只能作为已有工程的编写依据，不能替代缺失的库及索引字段。[S1]

## 浏览器正式脚本入口的补充核验

本节于2026-10-23追加，只读取公开官方资料，不操作用户浏览器或账号。工程连接数据位于`hardware/easyeda-pro/rev-a/design.json`；以下接口用于把连接数据变成真实编辑器图元，不能将数据文件本身认作原理图。

### 无扩展运行脚本

官方明确允许通过“高级→运行脚本”执行独立脚本，使用与扩展相同的`eda.<类实例>.<方法>`形式。每次执行的`eda`对象用后即弃，不应靠前一轮JS局部变量保存工程UUID；应将每步结果保存成任务文件再作为下一次输入。独立脚本不支持部分依赖扩展包或外部交互的API（官方以`SYS_IFrame`为例），常规库/原理图API仍需通过实际调用返回值确认。[S12]

不需要通过浏览器开发者工具读取隐藏应用状态或直接寻找全局`eda`。正式脚本入口已经提供受支持的执行环境。

### 最小只读探测

以下脚本只查询当前工程、版本和器件搜索结果，并通过官方文件保存接口导出JSON；不创建或修改工程，不读取用户账号信息。`getCurrentProjectInfo()`可能返回`undefined`，例如没有聚焦到已打开的工程文档；这应作为观察结果而不是自动创建工程的触发条件。[S13、S14]

```javascript
const current = await eda.dmt_Project.getCurrentProjectInfo();
const results = await eda.lib_Device.search(
  'LM66100DCKR', undefined, undefined, undefined, 10, 1
);
const report = {
  version: eda.sys_Environment.getEditorCurrentVersion(),
  isClient: eda.sys_Environment.isClient(),
  project: current ? {
    uuid: current.uuid,
    name: current.name,
    friendlyName: current.friendlyName
  } : null,
  devices: results
};
const json = JSON.stringify(report, null, 2);
await eda.sys_FileSystem.saveFile(
  new Blob([json], { type: 'application/json' }),
  'eda-probe.json'
);
eda.sys_Dialog.showInformationMessage(
  `版本：${report.version}\n搜索结果：${results.length}条\n已请求下载eda-probe.json`,
  'EDA接口核验',
  '关闭'
);
```

`SYS_FileSystem.saveFile(fileData: File | Blob, fileName?: string): Promise<void>`在浏览器使用下载接口，在Electron使用保存接口。返回void不包含可验证的磁盘路径，执行后仍须检查实际下载文件。`SYS_Dialog.showInformationMessage(content, title?, buttonTitle?)`同步返回void，显示窗口但不阻塞后续代码。旧`SYS_MessageBox`已弃用。[S14]

### 库查询与符号/封装关联

| 任务 | 已核实方法及重点 |
| --- | --- |
| 模糊搜索器件 | `eda.lib_Device.search(key, libraryUuid?, classification?, symbolType?, itemsOfPage?, page?)`；返回`ILIB_DeviceSearchItem[]`，默认系统库 |
| 精确属性搜索 | `eda.lib_Device.searchByProperties(properties, libraryUuid?, classification?, symbolType?, itemsOfPage?, page?)`；属性支持`name`、`supplierId`、`partNumber`、`partCode`、`value`等 |
| 器件详情 | `eda.lib_Device.get(deviceUuid, libraryUuid?)`；返回`ILIB_DeviceItem`或`undefined` |
| 符号元数据 | `eda.lib_Symbol.get(symbolUuid, libraryUuid?)`；返回属性，不等于引脚几何 |
| 封装元数据 | `eda.lib_Footprint.get(footprintUuid, libraryUuid?)`；返回属性，不等于焊盘几何 |
| 符号原始定义 | `eda.lib_Symbol.getDocumentSource(symbolUuid, libraryUuid?)`；返回3.0格式esym JSON字符串或`undefined` |
| 封装原始定义 | `eda.lib_Footprint.getDocumentSource(footprintUuid, libraryUuid?)`；返回3.0格式efoo JSON字符串或`undefined` |

器件详情的`association.symbol`含`{ type, uuid, libraryUuid }`，`association.footprint`可含`{ uuid, libraryUuid }`；使用这些关联查询符号与封装，不能把器件UUID当成符号UUID。详情还有`subPartNames`，用于识别多子部件器件。[S15]

官方特别说明模糊搜索可能返回近似型号或社区伪编号，如`C99xxxxxxx`。搜索成功不代表器件已匹配：必须复核完整型号、封装、属性和管脚。需要特定立创编号时用`searchByProperties({supplierId: 已核实编号}, ...)`，不得盲用第一条结果。[S15]

`LIB_Symbol.getDocumentSource()`官方示例还注明某版本的Promise可能未及时结束；应使用有界诊断等待并记录未完成结果，不能让一次源数据查询卡住整个生成流程。实际放置后引脚连接仍以`getAllPinsByPrimitiveId()`读回的绝对坐标为准。[S15、S16]

### 八页原理图的创建与连接顺序

1. 在当前任务的新工程中创建一个原理图，读回其默认图页，然后用`createSchematicPage(schematicUuid)`补齐页数；不要凭假设额外创建一张重复默认页。
2. 用`modifySchematicPageName(pageUuid, pageName)`命名，检查其布尔返回值并回读图页；用`dmt_EditorControl.openDocument(pageUuid)`打开目标页后再放图元。
3. 对每个已核准的库器件调用`sch_PrimitiveComponent.create(component, x, y, subPartName?, rotation?, mirror?, addIntoBom?, addIntoPcb?)`。可以直接传真实搜索项或详情对象，返回`undefined`代表创建失败。
4. 读取新图元的属性快照，再用`modify(id, {designator, otherProperty})`写入位号等属性；不要覆盖丢失库元件原有属性。多子部件器件按真实`subPartNames`处理。
5. `getAllPinsByPrimitiveId(id)`取得引脚号及坐标。引脚可能落在半格，如698.5；导线使用原始坐标，不四舍五入，也不按芯片脚号推算符号位置。
6. 连接明确网络使用`sch_PrimitiveWire.create(line, net?, color?, lineWidth?, lineType?)`；坐标可为单条正交折线或相连折线组。API会合并相连WIRE组，不相连线段不能在一次调用中强行组成一条导线。
7. 电源/地标识用`createNetFlag('Power'|'Ground'|'AnalogGround'|'ProtectGround', net, x, y, rotation?, mirror?)`；跨页信号端口可用`createNetPort('IN'|'OUT'|'BI', net, x, y, rotation?, mirror?)`。应以实际网表验证跨页同名网络，不把相同文本标签当作已连通证据。
8. 每页保存，等待拓扑刷新，然后检查对象数量、位号唯一性、网络、DRC和图片；最后再做整工程网表/BOM对照。不同图页的实际导出范围以运行结果核准，不能只检查当前一页就声称整板通过。[S10、S16]

### 网表、BOM与原生工程导出

| 产物 | API | 核验 |
| --- | --- | --- |
| 原理图网表 | `eda.sch_ManufactureData.getNetlistFile(fileName?, netlistType?)`，官方示例`'Protel2'` | 返回`File`或`undefined`；引脚编号重复等数据错误可能抛异常，需检查实际内容与连接数据 |
| BOM | `eda.sch_ManufactureData.getBomFile(fileName?, 'csv'|'xlsx', ...)` | 返回`File`或`undefined`；按位号和数量核对，不能只看导出按钮成功 |
| DRC | `eda.sch_Drc.check(true, false, false)` | 返回是否通过；详细模式第三参数true返回分组树，顶层数组长度是类别数，不是错误总数 |
| 专业版工程 | `eda.sys_FileManager.getProjectFile(fileName?, password?, 'epro'|'epro2')` | 需要工程下载权限；取到文件后用`sys_FileSystem.saveFile(file)`下载，再实际重导入验证 |
| 当前文档 | `eda.sys_FileManager.getDocumentFile(fileName?, password?, 'epro'|'epro2')` | 仅当前文档，不能代替完整工程交付 |

网表、BOM、原生工程均使用编辑器返回的真实File保存，不能把自制JSON直接更名为epro。DRC通过也不能替代本工具的电气设计、封装映射、温升和测量精度核验。[S6、S17]

本轮已找到官方SDK仓库`easyeda/easyeda-api-sdk`及`extension.json`配置文档；扩展菜单`registerFn`映射ES Module导出的函数，官方SDK构建得到`.eext`。但正式“运行脚本”入口已满足当前推进方向，因此本轮不构建、安装或分发自定义扩展。[S18]
