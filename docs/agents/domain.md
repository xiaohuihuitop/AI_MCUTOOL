# 领域文档

## 布局

采用 single-context：

- 项目根目录 `GLOSSARY.md`：领域术语。
- `docs/adr/`：架构决策记录。

## 探索前读取

探索代码前，读取术语表及与当前任务相关的 ADR。
文件尚不存在时继续工作，不单独提示缺失或预先创建占位文件。
术语和决策实际确认后，由 `domain-modeling` 按需建立文档。

## 使用规则

任务标题、方案、假设和测试名称使用术语表定义的领域词汇。
遇到尚未定义的概念，先判断是否沿用项目已有术语；
确有缺口时交由 `domain-modeling` 澄清。
方案与既有 ADR 冲突时，明确指出决策编号、冲突点和重新讨论的原因。
