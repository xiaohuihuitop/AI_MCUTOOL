## 2. 已确认的执行行为

| 项目 | 推荐行为 | 原因或影响 |
| --- | --- | --- |
| 人工与 AI 操作 | 多个客户端可同时观察，写操作由一个明确持有者控制；多步骤测试期间人工操作需要显式交接 | 避免 AI 测试中途被其他入口改变设备状态 |
| 操作持有者失联 | 标记会话失效并拒绝旧会话的新写操作；供电/充电保持，已接受的定时动作继续；不自动将操作权交给其他人。无在途动作且核对状态后，允许显式接管 | 失联不等于动作失败或要求断电；失联判定时间由实现确定并公开 |
| 充电时关闭主供电 | 拒绝直接关主供电或切换到外部电源，要求先显式关闭充电 | 保持只有真实电池通路允许充电的既有约束，不连带执行隐藏动作 |
| UART 禁用发送 | 停止接受新的发送请求，等待已接受的数据发送完成，再把 TX 设为高阻；等待有上限，超时明确返回未确认禁用，不静默截断。后续由调用方查询状态再决定 | 避免半帧发送和“已禁 TX”误报；超时后不擅自断电 |
| 短时缓存满 | 保留较新的测量/串口数据，明确报告被覆盖区间或无法精确统计的缺失 | 内存有限；持续记录依赖电脑端及时接收，不能承诺无限断网无损 |
| 记录失败 | 磁盘写入失败或记录队列溢出时将记录标为失败/不完整并保留已写文件；不声称完整保存，不隐式改变板上输出 | 软件必须区分数据完整性与设备运行状态 |
| 取消按键动作 | 取消指定动作并释放该动作控制的按键，不连带改变供电、充电或 UART | 取消的影响范围明确；序列自然结束也释放按键 |
| 动作与交互参数 | 按键序列步数/时长上限、忙时拒绝、去重容量、配网键长按时间、状态灯规则由开发时选择、记录并通过能力查询公开 | 无需用户逐项指定常规实现参数；不把设置步进当作物理精度 |
| 尚未校准 | 诊断可显示明确标为未校准的原始码/名义换算值；校准读数、质量标识和精度能力分开表达，不伪造校准系数或精度达标结果 | 软件流程可完整交付，整机准确度仍需要参考仪表验证 |
| 网络和连接 | 沿用首次配网/人工重新配网；通信失联保持输出，按键按原时长结束。连接或协议错误明确报告，不自动换通道、降级协议或重放动作 | 遵守项目既有约定；不借用 MKLink 的自动恢复行为 |

上述行为确认后，不因同一规则再次向用户请求确认。新增目标、改变这些行为或新增兼容/降级路径仍不属于自主实现细节。

- 在已确认范围内连续完成实现、编译、测试与修复，直到本轮交付项完成，不按阶段停下等待用户逐项批准。

- 先固定命令/数据契约和板级定义，再完成固件、后台、网页及 MCP 联调。测试围绕互锁、重复请求、会话交接、数据质量/缺失和生命周期，不只检查接口是否返回成功。
- 正式测试遵循产品工程的测试目录；临时脚本放在 `docs/temp/`。新增代码注释遵守中文 `AI:` 与接口 Doxygen 规则，文本使用 UTF-8 无 BOM。

- 工作限于本项目所需内容，不修改 MKLink 安装及其设备，不覆盖用户已有修改。沿用既有 Git 规则，不自动提交、推送或创建 PR。
- 可独立完成的工作持续推进；确有需要人工接线、参考仪表或实体按键的项目，集中列入交付报告，不以模拟测试或旧产物代替。不能完成的软件交付项如实标为未完成。

## 5. “一次完成”的验收边界

本轮以**完整首版软件、可运行交付物和可在当前环境执行的验证**作为完成标准。没有工具板及参考仪表时，以下实物项目单独保留为待验收：

- 本次固件在实际 N16R8 板上的启动、USB 枚举、Wi-Fi、长时间运行和供电稳定性。
- 五路触点的实际按下/释放延迟；MOS 先断后通间隔、反向阻断、压降、温升和带载表现。
- 电流正反向精度、零点/增益校准、四路近零准确区间和接入自负载。
- UART 实际速率、复位阶段 TX 高阻、不同上电顺序及反灌影响。

固件提供校准和参数设置流程；未经过实测的时序与校准参数必须标明状态，不能把软件初值写成硬件保证值。软件自动化检查不等于上述实物项目通过。

无人值守期间，电脑需保持开机、联网并避免休眠。确认后按本文件持续推进，不要求用户在开发过程中参与常规实现决策。
