## 发现的边界与修正

1. **单条直线创建接口尚有异常。** `pcb_PrimitiveLine.create` 在本轮两个参数组合中返回“无法创建直线图元”；没有通过取消验证或宣称成功掩盖。折线板框及文字接口独立验证成功，单条直线问题的根因尚未确定，正式布线前需单独核查。
2. **就绪状态接口需谨慎。** 本轮 `getDocumentReadyState` / `waitForDocumentReady` 返回 `notLoaded` / `false`，但同一文档能够创建文字、折线并截图。未依赖这一返回值宣称完整就绪；每步均实际读取目标项目、对象及结果。
3. **外部文件编辑必须遵守完整记录格式。** 初次测试脚本写入了 CRLF，且保留了末条记录缺少结束符的状态，导致板框未被重新解析。这是测试写入格式错误。依据官方规范，改为每条记录以 `|` 加 LF 结束后，板框恢复，关闭重开验证通过。脚本已修正，错误输入和失败回执保留。
4. **`open` 回执不保证数据已加载。** 新会话有一次立即读取项目得到 `undefined`；使用有界等待取得真实项目身份后继续，只读验证通过。
5. **PowerShell 标准输出差异。** 直接 `& lceda-pro.exe ...` 无法可靠捕获输出，客户端自己的帮助也说明这一点。本轮使用 Python `subprocess.run` 捕获，并检查退出码、顶层 `ok` 和业务结果。
