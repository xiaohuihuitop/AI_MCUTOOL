# 修复波形CSV直接打开时的中文乱码

## 复现

命令：`cd web; npx playwright test tests/charts.spec.ts -g '桌面波形导出|两组暂停'`。

修复前2项失败：按中文Windows默认编码读取实际导出字节时，预期的“设备,启动”变为乱码。原测试强制UTF-8读取，无法发现自动识别编码的错误。

## 根因

CSV正文是有效UTF-8，但没有编码标记。桌面直接将文本写成UTF-8字节，网页Blob的MIME编码不会保留为文件编码标记；表格软件直接打开时可能按系统中文编码解释。

复现文件2402个样本全部9列，UTF-8解码正确，电压3.9 V、电流0.012 A及0至120秒时间与夹具一致。排除文字在生成阶段被破坏及CSV列错位。

## 验证

`npm run build`通过，图表与波形13项回归通过；其中网页实际下载文件和桌面原生保存命令内容均验证中文编码。两组样本数、时间、数值、单位、暂停及隐藏通道导出行为保持一致。

找到截图对应的原始文件：`docs/temp/desktop-ui-1794650849498/MCUTOOL-电池-2026-11-14T14-33-01-268Z.csv`。电压、电流各144000条，跨度14399.899563秒，约10Hz；全部9列，时间无倒退，数字均可解析。首条电压0.0025 V、电流-0.000125 A。此核对确认导出结构与数值可读取，不作为硬件测量精度验收。

同目录生成`MCUTOOL-电池-2026-11-14T14-33-01-268Z-中文修复.csv`，仅新增UTF-8标记，原始正文逐字节一致。原文件SHA256：`99eaa8d70385aa9f1736a700222b6cf327f75236f5c2c16e3b1ea2296e2ab2ac`。
